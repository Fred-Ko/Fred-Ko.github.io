# 요청 범위와 원본 대조 검토

2026년 11월 12일. 기준은 원본 Jekyll 저장소의 `4f659e5`와 해당 빌드 결과, 사용자가 전달한 최초 HANDOFF의 디자인 시스템 v0.2, 이후 사용자의 명시적인 정정이다. 이전 작업을 새 문구 작성이나 기능 추가의 권한으로 해석했던 것이 문제였다. 아래에서 요청 없는 변경을 복원하고, 유지할 차이는 근거를 구분했다.

검토 범위는 홈·두 번째 페이지·글 28개·분류·태그·보관함·소개·404·검색·헤더·푸터·모바일 메뉴·댓글·통계·이미지·코드·메타데이터·RSS·사이트맵·PWA·배포 설정이다. 원본 템플릿의 존재뿐 아니라 실제 호출 여부와 CSS의 표시 상태까지 확인했다.

## 이전에 정한 기반과 기술적 대체

최초 HANDOFF는 디자인 시스템 v0.2를 ‘완료한 것’으로 전달했다. Pretendard·Space Grotesk·D2Coding, 색상 토큰, 컴포넌트, 셀프 호스팅 폰트, Pagefind, 페이지 전환, OG 생성 기반은 그 범위에서 유지한다. 이를 원본과 픽셀 단위로 같은 결과라고 주장하거나 새로운 개선의 근거로 확대하지 않는다. 위 표의 공통 문구·제목·정보 순서·기존 동작은 원본을 기준으로 복원했다.

다음은 개선 주장이 아니라 승인된 Astro 이전에 필요한 대체 구현이다.

- Jekyll/Liquid/Ruby 빌드를 Astro 정적 라우트·콘텐츠 컬렉션으로 교체한다. 기존 URL·글 ID·Worker 계약을 유지한다.
- jQuery·Bootstrap·GLightbox 등에 있던 메뉴·목차·카테고리 접기·이미지 확대·맨 위 이동을 Astro와 브라우저 기능으로 제공한다. 내부 기술 변경이 정보 삭제나 새 기능 추가의 근거는 아니다.
- Jekyll 이미지 크기 문법은 HTML로, 기존 인라인 수식 2개는 HANDOFF의 처리 방안에 따라 유니코드로 옮긴다. 원고 코드의 순서·내용과 표의 줄바꿈 23곳을 보존한다. 빈 이미지 대체 텍스트를 채우고 크기를 명시한다.
- 검색 엔진을 Pagefind로 교체하지만 실제 글 28개만 검색 대상이다. 디자인 시스템 예제가 실제 검색 결과에 섞이지 않는다.
- OG 이미지는 초기 HANDOFF의 생성기를 연결하며 28개 모두 1200×630으로 검증했다. 기존 글 제목·설명을 사용하고 새 홍보 카피를 넣지 않는다.
- 서비스워커의 원래 경로를 유지하며 기존 캐시를 정리한다. 원본 설정처럼 새 오프라인 캐시는 만들지 않는다.
- GitHub Pages 설정을 Astro 빌드에 맞게 바꾼다. 현재 작업은 로컬 변경이며 원격 푸시·병합·운영 배포는 실행하지 않았다.

## 재검증 자료

- `legacy-post-order.json`: 원래 목록 순서.

- `legacy-urls.json`: 이전 전 URL 117개.
- `posts-manifest.json` 및 이전 시험: 글 ID·본문·코드·이미지 변환 대조.

## 11월 13일 후속 화면 수정

사용자의 추가 화면 피드백에 따라 헤더의 내부 링크에만 적용되던 대문자 라벨 스타일을 제거했다. 모든 주 메뉴·외부 링크는 같은 서체·굵기·크기와 원래 대소문자 표기를 쓴다. 1200px 이상에서는 15px·굵기 500·간격 36px이며, 원본처럼 992px 미만에서 메뉴 버튼으로 전환한다.

사용자가 페이지 번호를 가운데로 정렬하고 로고를 더 크게 표시하도록 요청했다. 페이지네이션은 좌우 자동 여백으로 가운데 정렬했다. 브랜드는 20px에서 24px, DEV LOG는 11.2px에서 13px로 키웠다. Chromium·Firefox·WebKit의 1440·1024·768·390px에서 중앙 정렬·헤더 잘림·가로 넘침·모바일 메뉴를 확인했다. 로컬에만 반영했다.

사용자가 글 상세의 본문이 왼쪽으로 밀린다고 지적하여 본문 자체를 화면 중앙에 정렬했다. 본문과 목차를 합친 2열 영역을 중앙에 놓던 배치를, 본문이 가운데 열이고 양쪽 여백이 같은 3열 배치로 변경했다. 목차는 오른쪽 여백에 배치하고, 좁은 화면에서는 기존처럼 본문 위의 접힌 목차로 표시한다. 본문 글자의 왼쪽 정렬과 본문 폭은 유지한다.

같은 날 로컬 댓글 조회 오류를 조사했다. 8788번 로컬 Worker가 포트를 점유한 채 health·댓글 요청에 응답하지 않아 시간 초과가 발생했다. 해당 작업의 멈춘 프로세스만 종료하고 로컬 D1을 그대로 사용해 재시작했다. 4400번 미리보기를 통해 health·통계·세션·댓글 조회가 모두 200을 반환하며, 세 브라우저의 실제 API 연결에서 빈 댓글 안내가 정상 표시되는 것을 확인했다. 로컬 GitHub OAuth 자격 증명은 설정돼 있지 않으므로 실계정 로그인까지 완료했다고 주장하지 않는다.

## 파일과 발행 검사 정리

11월 13일 사용자 요청으로 소개 원고를 `src/content/pages/about.md`, 기존 글 호환용 운영 데이터를 `src/data/legacy-posts.json`으로 옮겼다. 런타임은 `docs/migration/`의 파일을 읽지 않는다. 이전 도구는 `scripts/migration/`, 엄격한 이전 시험은 `tests/migration/`로 모으고 일반 CI에서 분리했다. 이전 기준 URL·본문·화면 스냅샷은 검토 자료로 보존한다. 콘텐츠 안내는 `docs/CONTENT.md`, 검증 기록은 `docs/migration/VALIDATION.md`이며 과거 인계 기록은 `docs/migration/HANDOFF_HISTORY.md`로 옮겼다. 루트 인계 문서는 현재 상태·남은 작업만 안내한다.

빈 `.gitkeep`와 재생성 가능한 브라우저 결과를 정리한다. 원고 보관본·공개 이미지 경로·의존성·실행 중인 미리보기의 dist·로컬 D1은 유지한다. 기존 발행 도구 연결이나 로컬 OAuth가 완료됐다는 의미는 아니다.

## 통계 배치와 미리보기 재빌드 수정

사용자가 통계 확대·위치 조정을 요청해 조회수·좋아요·댓글을 본문 끝의 태그·공유 정보 위 중앙으로 이동했다. 아이콘은 24px, 숫자는 18px이며 좋아요 버튼 높이는 48px다. 세 브라우저의 데스크톱·모바일에서 크기·정렬·좋아요 동작을 확인했다.

빌드 도중 미리보기가 같은 dist를 읽어 글 URL이 잠시 404가 되는 문제가 있었다. 미리보기는 마지막 완성본을 메모리로 제공하고, Astro·검색 빌드 성공 후 생성하는 완료 신호로만 결과를 교체한다. 빌드가 실패하거나 아직 생성 중이면 기존 결과를 유지한다. 이전 화면이 사용하던 해시 기반 스타일·스크립트도 직전 결과에서 제공한다. 실제 글 경로나 원고는 변경하지 않았다.

## 본문 좌우 경계선

사용자의 요청으로 본문 바깥 24px 위치에 1px 세로선을 적용했다. 다크는 흰색 7%, 라이트는 검정 6%이며 768px 미만에서는 숨긴다. 선은 절대 위치의 장식 요소여서 원래 본문 폭·중앙 정렬·제목·목차 배치를 바꾸지 않는다. 클릭도 가로채지 않는다. 본문 배경 프레임은 추가하지 않았다.

## 코드 줄 간격

사용자가 코드 디자인 변경을 보류하고 줄 사이 간격을 지적했다. 프레임·색상·헤더·복사 버튼은 유지하고 일반 코드 줄 간격만 1.7로 넓혔다. 기존에는 text 코드 전체에 1.15가 적용돼 이벤트 흐름 설명까지 지나치게 좁았다. 박스 선 문자가 실제로 들어 있는 도식에만 1.15를 적용한다. 코드 원문은 변경하지 않았다.

사용자 후속 요청에 따라 일반 코드 줄 간격을 20px로 조정했다. 연결된 박스 도식의 간격과 그 외 디자인은 유지했다.

11월 13일 사용자가 Astro 작업 브랜치의 master 병합과 배포를 요청했다. 포크 해제는 사용자가 직접 수행했고 fork:false를 확인했다. 기존 발행 도구의 `블로그/**/_posts/*.md`·`assets/img/` 입력을 유지하도록 빌드 전 처리를 추가했다. 새 글·수정·삭제·동시 수정 충돌·코드 원문 유지·기존 형식 신규 글과 이미지의 실제 Astro 출력을 검증한다. Worker·D1·OAuth 운영 설정은 변경하지 않는다.
